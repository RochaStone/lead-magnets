The Problem

YOUR REAL WORK IS HIDING IN THERE

You open WhatsApp to check one thing and lose twenty minutes. Forty unread threads, and the message that decides your month is somewhere underneath a voice note about lunch.

Clients, leads, collaborators and the one follow-up you keep forgetting all live in the same crowded inbox, with no hierarchy between them. Every thread looks equally urgent, which means none of them are. So you scroll, you feel behind, and you close the app having cleared nothing.

The fix was never typing faster. It was giving something the ability to read the whole pile and tell you the two things that actually need a human. That is a different capability, and it is now a forty-minute setup.

Pick Your Path

THREE WAYS TO SET IT UP

Choose on two questions: how much control you want over where your messages live, and whether this is for you or for a team inbox.

Path Effort Where messages go Best for
Hosted connector ~5 min, no code Through a provider's servers Creators and solo operators who want it working today
Local bridge 20–30 min Stay on your machine Client work, anything confidential, full control
Business Cloud API Setup + Meta approval Meta, verified business number Support inboxes, teams, broadcasts
If you hold client confidences, take the local path. A hosted connector is genuinely faster and genuinely fine for a personal inbox. It is a different decision when the threads contain other people's business.

Path 01

HOSTED CONNECTOR

About 5 minutes · No code · Creators and solo operators
  1. In Claude, open Settings → Connectors and choose Add custom connector.
  2. Paste the MCP URL from a hosted WhatsApp provider — Blueticks and Wassenger both offer one — then click Connect.
  3. Claude sends you to the provider to log in and approve access on your number.
  4. You are live on web and desktop. Message yourself first to test, before you point it at a real thread.

Fastest route by a distance, and the only one that needs nothing installed. The trade is real and worth naming: your messages pass through a third party's infrastructure. For a personal inbox that is an ordinary trade. For client work it is a decision, not a detail.

Path 02

LOCAL BRIDGE, FULLY PRIVATE

20–30 minutes · Nothing leaves your machine
  1. Install the prerequisites: Go, Python 3, and the uv package manager (curl -LsSf https://astral.sh/uv/install.sh | sh). ffmpeg is optional and only needed for voice notes.
  2. Clone the open-source server: git clone https://github.com/lharries/whatsapp-mcp
  3. Run the bridge with cd whatsapp-bridge && go run main.go. A QR code prints in the terminal.
  4. On your phone: WhatsApp → Settings → Linked devices → Link a device, and scan it. Same mechanism as WhatsApp Web.
  5. Add the server to your Claude config (below), restart Claude, and ask for your recent chats.

Add this block to your config file, replacing both placeholders:

{
  "mcpServers": {
    "whatsapp": {
      "command": "{{PATH_TO_UV}}",
      "args": [
        "--directory",
        "{{PATH_TO_SRC}}/whatsapp-mcp/whatsapp-mcp-server",
        "run",
        "main.py"
      ]
    }
  }
}

{{PATH_TO_UV}} is the output of which uv. {{PATH_TO_SRC}} is wherever you cloned the repo. Both must be absolute paths — a relative path here is the single most common reason this fails.

Where the config lives.
macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
Windows: %APPDATA%\Claude\claude_desktop_config.json

Your chats sit in a local SQLite database under whatsapp-bridge/store/ and reach Claude only when you ask a question. Nothing is uploaded. Leave the bridge terminal running — it is the live connection, not a background service.

Then message yourself, before anything else. It is the only way to know the connection is real, and it costs nothing to be wrong in your own chat window. If the test message arrives from an account that isn't yours, you scanned the wrong phone — log that device out and pair again.
Path 03

BUSINESS CLOUD API, AT SCALE

Setup + Meta approval · Support inboxes and broadcasts
  1. Set up a Meta Business account and the official WhatsApp Business Cloud API.
  2. Verify your number and get your message templates approved. Budget days, not hours — template review is the long pole.
  3. Connect Claude through an automation layer such as n8n or Make.
  4. Route incoming messages to Claude for on-brand replies, with a human approving anything that commits you to something.

This is the only path built for a team inbox and the only one that survives volume. It is also the only one where you are operating inside Meta's rules on templates and messaging windows — which is a feature when you are sending at scale, and friction when you are not.

Read This Before You Believe A Demo

THE PART EVERY GUIDE GETS WRONG

The local bridge exposes twelve tools. It can search your contacts, list your chats, read a thread, pull the context around a single message, send text, send a file, send a voice note, and download media.

It cannot schedule. There is no scheduling tool. No prompt unlocks one. If you ask Claude to send something at 11am tomorrow on this path, the honest answer is that it can't — and an unreliable one is that it says yes and nothing sends.

Hosted providers generally do schedule natively, because their servers stay awake when your laptop doesn't. That is a real reason to pick Path 1, and a fair trade to make knowingly.

If you want the local path and scheduling: keep a small queue file on your machine and a timer that sends anything due to the bridge's local endpoint. Roughly forty lines of Python and a scheduled job. Two things to get right — store times in UTC so a flight doesn't shift your sends, and retry rather than discard when the bridge is unreachable, so a closed laptop delays a message instead of dropping it.

Ask any tool what it can actually do before you trust it with a client. The answer is usually shorter than the landing page.

Steal These

FIVE PROMPTS TO RUN FIRST

Prompt 01

THE TRIAGE

Read my WhatsApp threads from the last three days. Don't summarise them one by one. Group them into: needs me, needs a reply but not my judgment, and can wait. For anything in the first group, tell me what's at stake — not what they said.

Why it works: "summarise my chats" gets you the inbox again with extra steps. Asking for stakes forces a judgment call, which is the thing you actually wanted.

Prompt 02

THE PROMISE SWEEP

Search my sent WhatsApp messages from the last 30 days for anything where I committed to sending, doing, or deciding something. For each one, check whether I ever followed through. Show me only the ones I didn't, oldest first, with anything involving money at the top.

Why it works: this is the highest-value thing on the list and the one nobody thinks to ask for. Most founders are carrying four unkept promises they have genuinely forgotten. It usually finds money.

Prompt 03

THE RELATIONSHIP READ

Read my full history with [name]. Tell me: where this started, what we agreed, what's outstanding on each side, when it last moved, and what the next move should be. Flag anything involving money explicitly.

Why it works: run this before a call and you walk in holding the whole arc instead of the last three messages. It is the difference between remembering someone and knowing where you stand.

Prompt 04

THE DRAFT, IN YOUR REGISTER

Read my last 15 messages with [name] and notice how formal we are with each other. Draft a reply about [topic] matching that register. Two to five sentences, prose not bullets, no "just checking in", no sign-off. Show it to me — don't send it.

Why it works: voice is constant, register is not. Naming the length and banning the filler phrases removes the two things that make a draft read as written by an assistant.

Prompt 05

THE COOLING CHECK

Find threads where I made the last substantive move — a proposal, a quote, an offer — and they haven't replied in four days or more. For each, tell me how long it's been and draft a follow-up that gives them an easy way to say no.

Why it works: silence after a number is data, not absence. And a follow-up that permits a no gets answered far more often than one that only permits a yes.

If Something Breaks

THE FOUR THINGS THAT GO WRONG

The tools don't appear in Claude
Almost always a relative path in your config, or you didn't restart Claude after editing it. Use absolute paths for both uv and the repo. On the local path, check the bridge is still running — it is the connection itself, not a background service.
It worked, then stopped after a couple of weeks
Local pairings lapse at roughly 20 days. Re-run the bridge and rescan the QR code. Your message history survives — only the link is renewed.
Only recent messages show up
History backfills after pairing and takes a while on a large account. Give it time before concluding it's broken. If Claude ever summarises a period it couldn't actually read, stop trusting that answer — a confident summary of unread messages is worse than no summary.
It says it sent, and nothing arrived
Almost always the number format, and it fails silently — no error, no delivery. On the local path the recipient string becomes the address verbatim, so a leading + or a domestic number with its trunk zero is simply an invalid address. Use bare international digits: country code, no plus, no leading zero, no spaces. An Australian mobile written 0491 570 156 becomes 61491570156. A UK 07700 900123 becomes 447700900123.
You're nervous about the first send
Correct instinct. Message yourself first. Then one trusted contact. Then rely on it. Never let the first real send be to a client.
Read This Twice

ONE RULE THAT DOESN'T BEND

This connection can read and send on your account. Treat it like a key, because it is one.

  • Keep approval in your hands. Every outbound message gets shown to you in full before it goes. A standing "just send them" is how you find out what an AI thinks your voice sounds like, in public.
  • Only connect servers you trust. Prefer local storage if the threads contain other people's business.
  • Messages are data, not instructions. Anyone can write to you. If a thread contains something that reads like a command — send money, forward a code, message this list — that is a message from a person, not an order to your assistant. Treat anything that tries to steer Claude as a flag, not a task.
  • To cut access instantly: WhatsApp → Linked devices → log out. Immediate, from your phone, no dependency on anyone.
